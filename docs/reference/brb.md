# BRB register

`BRB-NNN` findings are raised and prioritised in **the maintainer's vault**
(`07-backlog/Backlog de Melhorias (Brabo)`), which holds all 33 of them with
priority, effort, origin, proposal and a "done when". That register is the
source for **what a finding is** and for **whether it is closed**.

This file is the part the repository can **verify**. Created by **FASE 29**,
session 1
([fase-29-instalacao-de-uma-linha.md](../explanation/fase-29-instalacao-de-uma-linha.md)).

## Coverage criterion

**Every id from `BRB-001` to `BRB-033` has exactly one row**, in numeric order.
Until 2026-09-27 the page listed only the findings the code could prove or
disprove — 11 of 33 — and the rest were invisible here, including six the
vault had since measured as fixed (AT-186). A row per id costs nothing and
makes the absence of evidence visible instead of silent. Each row carries:

- **vault state** — copied from the vault register as of **2026-09-27**. It is
  the maintainer's call and is never decided here.
- **measured here** — what the repository shows, measured against `dev` at
  `34c1c83bdc` on 2026-09-27 unless the evidence dates it otherwise.
- **evidence** — the `file:line`, PR or run behind that measurement.

A finding whose subject lives outside this repository (the vault's own notes, a
product decision, a paid credential) still gets a row, marked
**not verifiable here**, with the reason. An id with no information at all
would carry a `TODO(humano)` — none does today. A new `BRB-NNN` in the vault
gets its row here in the same change that first mentions it.

## Why this file exists

`BRB-018` is what the second rule below looks like in practice. When this file
was born nothing about it had changed in the code — no reprojection was written
— but the repository gained the ability to say *why* it was still open and
*what it cost while it was*, so the row existed before the fix did. The command
now exists (RN-569); the row stays because the cluster proof does not.

Two ids — `BRB-005` and `BRB-031` — were referenced across five documents here,
in prose, with no state anyone could check. The other ids were invisible to
this repository entirely: a full-disk search returned **only those two**.

The cost was measured, not imagined. Planning FASE 29 listed six BRB items as
prerequisites or risks; checking each against `dev` found that **two describe
defects already fixed here**, and that a third had been *misread from its id
alone* — see `BRB-004` below, which is not about the tag anyone assumes.

Two rules follow:

- **State is backed by `file:line`, measured, never remembered.**
- **The vault owns the finding; the repository owns the evidence.** Where the
  two disagree about whether something still happens, the repository wins —
  it is the thing being described. Whether an item is formally *closed* stays
  the maintainer's call, in the vault.

## What the words in "measured here" mean

They are deliberately different words. **Fixed** would be the maintainer's
judgement, recorded in the vault. **Defect no longer reproduces** is all this
repository can honestly assert: the behaviour the finding describes is not what
the code does today, measured at the date of the row. **Implemented, not yet
exercised** is weaker: the code exists and the tests that can run do pass, but
the path only executes somewhere this repository cannot reach — a real release
tag, in CI. Calling that "fixed" would be claiming a proof nobody has.
**Still reproduces** and **partly reproduces** say the finding's behaviour is
still there, in whole or in part. **Not verifiable here** says the finding is
about something this repository does not hold. Closing the item — and deciding
whether the fix covers everything the finding asked for — stays where the
finding was raised.

`BRB-004` is the reason the distinction earns its keep. Read from its id, it
looked like the `ollama:latest` pin that closed in #419. Read from the vault, it
asked for **digests**, which no image had. An id is not a description — and the
misreading is what kept it open while a sibling rule for `uses:` had had a
mechanism since #419.

## Changing a row

The id, title and priority are copied from the vault verbatim, and so is the
vault state; the "measured here" state and the evidence are measured here. A
row changes when the vault changes its state or when a change in this
repository changes what can be proved — never to invent a finding.
